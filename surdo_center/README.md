# АудиоМед

Начальная рабочая версия дипломного проекта «Автоматизированная система управления сурдологическим центром».

На текущем этапе реализованы ролевой вход, профили врачей, картотека пациентов, динамическое расписание, запись/перенос/отмена приёма, рабочее место врача, история посещений, услуги, оплаты и модели аудиометрии. Структура подготовлена к будущей двусторонней интеграции с внешней системой записи. СППР остаётся отдельным следующим этапом и этой доработкой не изменяется.

## Архитектура

- `accounts` — сотрудники, роли и контроль доступа;
- `patients` — карточки пациентов, поиск и проверка дублей;
- `scheduling` — графики, исключения, расчёт свободных интервалов и записи;
- `medical` — врачебный приём и медицинское заключение;
- `billing` — услуги, оказанные услуги и оплаты;
- `audiometry` — обследования, исходные измерения и вычисленные показатели;
- `integrations` — внешние идентификаторы, сопоставления, входящие заявки и журнал синхронизации без сетевой интеграции;
- `dashboard` — отдельные рабочие панели ролей;
- `config` — общая конфигурация Django;
- `scripts` — служебная проверка и первичная настройка PostgreSQL.

Система использует только PostgreSQL. SQLite не является рабочей базой проекта.

## Требования

- Python 3.12;
- PostgreSQL 17 или 18;
- Windows 10/11 для автоматического запуска BAT-файлом.

## Первый запуск в Windows

1. Убедитесь, что служба PostgreSQL запущена.
2. Проверьте параметры проекта в `.env`.
3. Запустите `start_surdo_center.bat` двойным щелчком.

BAT-файл использует исключительно собственное окружение `.venv` внутри проекта. Если окружения ещё нет, оно создаётся автоматически. При первом подключении скрипт попросит пароль администратора PostgreSQL, создаст отдельную роль `surdo_center_app` и базу `surdo_center`, после чего применит миграции.

Пароль администратора PostgreSQL используется только во время настройки и не сохраняется. Приложение работает от отдельной роли с параметрами из `.env`.

## Ручной запуск

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts\provision_postgresql.py
python manage.py migrate
python manage.py restore_initial_state
python manage.py initialize_system
python manage.py runserver
```

При запуске через BAT система открывается по адресу `http://127.0.0.1:8010/`. Отдельный порт исключает конфликт с другими учебными проектами на компьютере.

Файл `.env` содержит локальные секреты и не должен попадать в систему контроля версий. Публичный шаблон настроек находится в `.env.example`.

## Начальные учётные записи

Локальные учётные записи могут быть перенесены из исключённой из Git резервной копии.
Пароли в репозитории не хранятся; администратор должен установить их локально перед использованием системы.

## Проверка проекта

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Проверками охвачены роли, нормализация телефона, свободные интервалы, выходные врача, защита от двойной записи, отмена и перенос записи, а также основные ролевые экраны.

## Сохранность прежнего состояния

Старый `db.sqlite3` не удалён, но приложение больше его не открывает. Одноразовый экспорт исходных данных сохранён локально в `.local-backups` и исключён из Git. Команда `restore_initial_state` переносит это состояние только в пустую PostgreSQL; при последующих запусках повторного импорта не происходит. После подтверждения переноса файл остаётся только резервной копией.

## Динамическое расписание

Продолжительность новой записи берётся из `Service.duration_minutes`, а границы `start_time`/`end_time` сохраняются в самой записи. Поэтому изменение справочника услуг не меняет исторические и уже созданные записи. `DoctorScheduleTemplate.booking_step_minutes` задаёт только допустимый шаг начала (например, 15 минут).

Свободное время вычисляется из регулярного графика, нескольких исключений в день, существующих записей и продолжительности услуги. Отменённые записи время не блокируют. Пересечения дополнительно запрещены PostgreSQL `ExclusionConstraint`, поэтому защита действует и при одновременных запросах.

## Миграции текущей доработки

Новые миграции создаются и проверяются на отдельной тестовой PostgreSQL, но не применяются к рабочей базе автоматически. Перед применением администратор должен создать резервную копию и убедиться, что она читается:

```powershell
pg_dump --format=custom --host=HOST --port=PORT --username=USER --dbname=DATABASE --file=.local-backups\before_migrate.backup
pg_restore --list .local-backups\before_migrate.backup
```

Только после успешной проверки резервной копии следует просмотреть план и применить миграции:

```powershell
.\.venv\Scripts\python.exe manage.py migrate --plan
.\.venv\Scripts\python.exe manage.py migrate
```

Архитектурные решения и открытые вопросы интеграции описаны в `docs/database_design.md`. Актуальная редактируемая ER-диаграмма находится уровнем выше проекта в файле `ER_диаграмма_АСУ_сурдологического_центра_актуальная.drawio`.
